One problem, two skills: Agentic AI + Data Lakehouse, learned week by week.

Pace: ~1 hour/day · This file is the course's front door (the week-by-week schedule) · Follows hiver/ROADMAP.md · Status ledger: PROGRESS.md · Want the pitch, rules, and setup first? COURSE.md → SETUP.md

Two sacred rules (from OpenHiver) — every week keeps them in sight: 1) a clean clone must reproduce the headline numbers in <15 minutes (use tiny, subsampled data); 2) every headline number carries a "what's misleading about this?" note. Exit checkboxes are the definition of "done" — a week isn't done until its boxes are ticked and its journey/0X-*.md journal is written.
Agentic AI: modules 0–9 Lakehouse: weeks 1–5 The build: phases 0–6 Teaching: concepts 01–30

The shape of the plan

T-shaped learning. You never "finish" one subject before starting the other — Phase‑0 gives you a shallow, provable slice of both (tool calling + a medallion pipeline), then the Hiver build integrates them and supplies depth on demand. Lakehouse weeks 2–5 happen inside Hiver phases 2–5; LangGraph (agentic module 6) is learned inside phase 3. Concepts are read at the moment their phase uses them (never before — that's the course rule), so concept files marked planned are linked to the index: they get written when the phase starts.

Fast track (if 3–4 weeks / more hours are available)

Skip Phase 5, tighten Phase 2 (silver-first, minimal gold), and overlap labelling with the agent. The ROADMAP's fast path is Phases 1 → 2 → 3 → 4 → 6 — the full 10-week plan below is the recommended full-mastery route.

Week-by-week (1 hour/day ~ 10 weeks)

Week 1 — Phase 0 exit + Phase 1 kickoff

Goal: prove the two foundations

Agentic AI (tracks 0A)

  • Re-run your tool-calling loop: agentic-ai-40-days/5.tool_calling/tool_calling_homework.py
  • Explain the bind_tools → tool_calls → execute → re-invoke loop in your own words (the Phase-0A exit item)
  • If flaky, review 5.tool_calling/details.md + agentic_loop.md

Lakehouse (track 0B)

  • podman-compose up -d in lakehouse/
  • Re-run lakehouse/week-1/bronze_silver_gold.py; screenshot the RustFS buckets
  • Answer "why is Bronze append-only?" (Phase-0B exit item)

The build + concepts

  • Fill journey/00-start-here.md (gates Phase 1): temp 0 vs 1.0 AND Bronze vs Gold — and how a tool-calling agent would retrieve from a Gold table
  • Download the data — Kaggle twcs.csv (~3M rows), keep it outside the repo
  • Concepts: read before/while working — see Phase 0 card below

Week 2 — Finish Phase 1, start Phase 2

Goal: framing decided, ingest begins

Agentic AI

  • Intent taxonomy design (v0: 6–9 intents: flight_delay, baggage, refund, booking_change, rude_service, praise, other…)
  • Task decomposition: classify → draft → route as 3 sub-tasks; define "good = ?"

Lakehouse

  • Profile the 1% sample with pandas: shape, missing response_tweet_id, language mix
  • Stand up lakehouse/ structure: bronze/ silver/ gold/ buckets
  • Bronze ingest: 1-brand raw subset, immutable, partitioned by created_at

The build + concepts

  • Pick the brand (shortlist: AmericanAir / AppleSupport / AmazonHelp — high volume, clear intents)
  • Write journey/01-problem-framing.md: brand + why, intents, out-of-scope list, "good =" definition
  • Concepts: Phase 1 → Phase 2 cards below

Week 3 — Phase 2: Silver threading

Goal: a queryable clean-thread table

Agentic AI (supporting)

  • Data prep for LLMs: thinking about what clean threads look like as retrieval inputs (dedup, language filter)
  • Acknowledge heavy loss: many inbound tweets have no reply — "single-tweet threads" are valid

Lakehouse

  • Silver: clean + thread-reconstruct (join tweet_id ↔ response_tweet_id), dedup, language-filter
  • Write Silver as an Iceberg table (not just Parquet) — this completes lakehouse week 2
  • Centerpiece of the journal: "% dropped + why"

The build + concepts

  • journey/02-lakehouse-ingest.md draft: row counts bronze→silver→gold, % dropped + why, partition choice
  • Export eval_pool AS SOON AS Silver stabilizes — labelling is the long pole, parallel with Phase 3
  • Concepts: Phase 2 card below

Week 4 — Finish Phase 2 (Gold), start Phase 3

Goal: gold for retrieval + baselines

Agentic AI

  • Read module 6 (LangGraph) — the planned gap; read when the phase starts
  • Refresh module 4 prompting (few-shot, instruction-based) + module 5 tool calling + module 7 (simple RAG)

Lakehouse

  • Gold: threads, intent_candidates (weak keyword labels), eval_pool (stratified source, 200–300 rows)
  • Export eval_pool to CSV — holdout rule: these tweet_ids are EXCLUDED from the retrieval index

The build + concepts

  • Baseline A (trivial): regex/keyword classifier + template reply + always-escalate router
  • Baseline B (simple): zero-shot Groq classifier + prompt-only drafter (no retrieval)
  • Concepts: Phases 3 card below

Week 5 — Phase 3: Agent v0 on LangGraph

Goal: working agent over Gold

Agentic AI

  • Build the 3-node graph: classify → retrieve → draft + route
  • Tools: search_historic_resolutions(thread) (over Gold) + escalate(reason)
  • Prompts reuse module-4 techniques; temp 0; few-shot + instruction-based

Lakehouse

  • Gold tables as the retrieval source (brand's historic resolutions)
  • Enforce the holdout at index build + in agent/graph.py + tools.py (retrieval must never touch a golden example's own thread)

The build + concepts

  • Run all 3 (A, B, v0) on eval_pool; log accuracy + cost/latency
  • Grounding caveat in framing: ~2017 data = "follows the brand's documented historical pattern", not "is correct policy now"
  • journey/03-agent-v0.md: prompts pasted, 5 errors pasted, what RAG fixed vs didn't

Week 6 — Finish Phase 3, start Phase 4 (labelling)

Goal: agent done, golden set growing

Agentic AI

  • Tune/troubleshoot Agent v0 on leftover failures; cost & latency pass
  • Read eval concepts (17–20, written when Phase 4 starts): precision/recall/F1, LLM-as-judge, BLEU/ROUGE, Cohen's κ

Lakehouse

  • Week 5 in practice later; for now: keep eval_pool stable so labelling doesn't re-run on moving data

The build + concepts

  • Hand-label 150–250 rows from gold/eval_pool, stratified by intent + confidence: text, true_intent, good_reply_traits, should_escalate, notes → eval/golden.csv
  • Labelling is the long pole — keep going every spare hour this week and next

Week 7 — Phase 4: eval harness + judge

Goal: reproducible numbers under 15 min

Agentic AI

  • LLM-as-judge rubric (groundedness, tone-match, actionability, no-hallucination) with a DIFFERENT model/prompt/temperature than the drafter
  • Failure taxonomy; re-score 30–50 judge outputs → report Cohen's κ honestly

Lakehouse

  • Week 5 in practice: DQ checks + lineage (which silver version → which golden label → which score)

The build + concepts

  • Metrics: intent acc/F1 · escalation precision/recall · reply BLEU/ROUGE + judge · retrieval hit-rate/recall@k (did the right thread get retrieved?)
  • eval/run.py reproduces headline numbers in <15 min
  • journey/04-evaluation.md + mandatory "what's misleading about my headline number?" draft + journey/decisions.md

The build + concepts

  • Concepts 21–25 (written when Phase 5 starts): memory & thread state, DAG orchestration, DQ/lineage, confidence thresholds/routing, guardrails
  • journey/05-harden.md draft: before/after failure examples

Week 9 — Phase 5: Harden, part 2 + Phase 6 start

Orchestration, ops
